# go-encryptions/whirlpool

[![ci](https://github.com/go-encryptions/whirlpool/actions/workflows/ci.yml/badge.svg)](https://github.com/go-encryptions/whirlpool/actions/workflows/ci.yml)
[![Go Reference](https://pkg.go.dev/badge/github.com/go-encryptions/whirlpool.svg)](https://pkg.go.dev/github.com/go-encryptions/whirlpool)
[![License: BSD-3-Clause](https://img.shields.io/badge/License-BSD--3--Clause-blue.svg)](LICENSE)

**Whirlpool** hash (ISO/IEC 10118-3, 512-bit digest) as a standard `hash.Hash`: the final 2003 version, with the revised S-box and the diffusion matrix `cir(1, 1, 4, 1, 8, 5, 2, 9)`. Table-driven, no cgo, no dependency outside the standard library. Plain Go everywhere, plus an arm64 assembly kernel (`compress_arm64.s`, generated with go-asmgen by `internal/genasm`) that keeps the whole round in registers.

Its first consumer is [`go-fde/veracrypt`](https://github.com/go-fde/veracrypt), which needs Whirlpool-512 as one of the PRFs of PBKDF2-HMAC to derive header keys of VeraCrypt volumes.

## Install

```sh
go get github.com/go-encryptions/whirlpool
```

## Usage

```go
import "github.com/go-encryptions/whirlpool"

h := whirlpool.New() // hash.Hash: Write, Sum, Reset, Size() == 64, BlockSize() == 64
h.Write(data)
digest := h.Sum(nil)

sum := whirlpool.Sum(data) // [64]byte, one shot
```

It plugs into `crypto/hmac` and PBKDF2 like any `hash.Hash`: `hmac.New(whirlpool.New, key)`. `Sum` appends to its argument and does not change the running state.

## Saving the state

The hash implements `encoding.BinaryMarshaler`, `encoding.BinaryUnmarshaler`, `encoding.BinaryAppender` and `hash.Cloner`. The state is 140 bytes: the magic `wrl\x01`, the eight chaining words, the 64-byte block buffer and the byte count. `UnmarshalBinary` refuses a state of the wrong length, a foreign magic, or a buffer that disagrees with the count, and then leaves the receiver unchanged. This is what lets `crypto/hmac` (and so `crypto/pbkdf2`) save the keyed inner and outer states once instead of rehashing the key block on every call.

## Not constant-time

The round function is eight 256-entry tables of 64-bit words indexed by state bytes. Those look-ups use secret-dependent addresses, so **table lookups are not constant-time**: a local attacker with cache-timing access could observe them. Do not use it where that matters (hashing public data and deriving keys from a password in a local tool are the intended uses).

## Verification

- `testdata/botan-whirlpool.vec`: Botan's own `src/tests/data/hash/whirlpool.vec`, hashed one-shot and in uneven pieces.
- The ISO/IEC 10118-3 examples of the reference implementation's `iso-test-vectors.txt` (empty string, `a`, `abc`, `message digest`, the alphabet, the 62-character mix, eight times `1234567890`, `abcdbcde...`) and the one-million-`a` vector (`0C99005B...E4ED8B01`).
- `testdata/botan-diff.vec`: a differential corpus of 500 messages (lengths 0 to 199, then random up to 2000 bytes) hashed by the Botan 3.14.1 command line, generated by `internal/genbotan` (`go run ./internal/genbotan`). Regenerating needs `botan` on the `PATH`.
- `openssl dgst -whirlpool` (OpenSSL 4.1.0, legacy provider) was run on `abc` and agrees with the ISO vector.
- The unrolled round is checked against the reference loop form of the round transformation.
- `FuzzChunking` cross-checks arbitrary chunkings of a message against the one-shot digest; CI runs it for 60 seconds, and its corpus is committed in `testdata/fuzz` (with seeds in the test). `FuzzUnmarshalBinary` feeds arbitrary bytes to `UnmarshalBinary` and checks that an accepted state marshals back to the same bytes.
- Marshalling: a saved state restored after every buffer fill from 0 to 130 bytes goes on exactly like the original, and HMAC and PBKDF2 give the same bytes with and without the marshalling path.
- CI: race detector and a 100 % statement-coverage gate on amd64 and arm64; the same tests under QEMU on big-endian s390x and on riscv64; `govulncheck`.

## Implementation

A port of Barreto and Rijmen's reference (`Whirlpool.java` and `Whirlpool.c` version 3.0 of March 2003, public domain): the S-box string of the reference builds eight tables `C[t][x] = S[x] . cir(1, 1, 4, 1, 8, 5, 2, 9)` rotated right by `t` bytes (field polynomial `x^8 + x^4 + x^3 + x^2 + 1`, `0x11d`), the round constants come out of the first tables as in the reference, and the compression is the Miyaguchi-Preneel construction `H = W_H(m) ^ H ^ m` over ten rounds, the key schedule running in lock step with the state. The round is unrolled over sixteen locals. Padding is the `0x80` byte, zeros up to 32 bytes short of a block boundary, and the message length in bits as a 256-bit big-endian integer (this package counts up to 2^67 bits; the high bits are zero for any input that fits in memory). Digests are the 64 bytes in the order the ISO document prints them.

Bibliography opened for this work: the Whirlpool reference archive (`Whirlpool.java`, `iso-test-vectors.txt`), Botan's `whirlpool.vec`, the Botan 3.14.1 command line and the OpenSSL 4.1.0 command line.

## Performance

`BenchmarkSum1K` and `BenchmarkSum64K` hash a 1 KiB and a 64 KiB buffer with no allocation. The reference is Botan 3.14.1 (`botan speed --buf-size=N Whirlpool`, wrapped as Go benchmarks by `internal/botanbench` so that `abbench` can interleave it). Apple M4 Max (arm64), one core (`GOMAXPROCS=1`), 6 interleaved rounds by `abbench --max-load 8`, summarised with `benchstat`; both result files hold 12 `^Benchmark` lines.

| per call | this package | Botan 3.14.1 | ratio |
|---|---|---|---|
| 1 KiB | 2.864 µs ± 6 % (341 MiB/s) | 2.487 µs ± 6 % (393 MiB/s) | this package **1.15x slower** |
| 64 KiB | 171.1 µs ± 8 % (365 MiB/s) | 147.7 µs ± 1 % (423 MiB/s) | this package **1.16x slower** |

Times are per call, so lower is better. This package is slower than the reference here and the gap is an open defect, tracked in the issue tracker. `internal/botanbench` reports Botan's rate as ns/op, and the ratios are computed from the two result files' medians. No SIMD is used.

### PBKDF2-HMAC

`BenchmarkPBKDF2HMAC` is the VeraCrypt shape: `crypto/pbkdf2` with HMAC-Whirlpool, 1000 iterations, 64-byte output. Before is v0.1.0 (no state saving), after adds marshalling; same machine and method (6 interleaved rounds, `abbench --max-load 8`, `benchstat`).

| 1000 iterations, 64-byte output | v0.1.0 | with marshalling | change |
|---|---|---|---|
| time | 1050.9 µs ± 1 % | 737.5 µs ± 1 % | **-29.8 %** (1.42x faster) |
| allocation | 656 B | 944 B | +288 B per call (the saved states) |

Per iteration HMAC-Whirlpool with a 64-byte digest costs 6 compressions without state saving (inner: key block, 64-byte message, padding block; outer: the same) and 4 with it, so 1.5x is the ceiling and 1.42x is measured. (The padding block comes from the 64-byte message filling a whole block, so the 2x of "4 against 2" does not apply to a 64-byte-digest hash.)

Reproduce the throughput numbers with: `go test -c -o whirlpool.test .`, `go test -c -o botan.test ./internal/botanbench`, then `abbench --base ./whirlpool.test --head ./botan.test --max-load 8 -n 6 -- -test.bench . -test.run '^$'`.
